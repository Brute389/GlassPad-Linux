Third-party notices — GlassPad Linux port
=========================================

What this file is for

The GlassPad Linux port is distributed as its own Python source, plus — in the
AppImage only — one upstream binary described under "Shipped inside the AppImage"
below. Nothing else is bundled. The packaging tools deliberately ship no host
libraries, because libgtk4-layer-shell has to match the machine's own libwayland
and GTK 4: a bundled copy that disagrees produces a blank overlay rather than an
error message.

So the entries below are listed so you know what you are running, not because this
port conveys copies of them. Replace any of them whenever you like — nothing is
linked statically, which is the whole point. Your distribution keeps the exact
licence text for each package it installed (on Arch, /usr/share/licenses/<pkg>/).

3. Numbers copied, not code
---------------------------

glasspad/xd360.py defines the constants of the Xbox 360 uinput ABI — struct
layouts and key codes — taken from the Linux kernel headers input-event-codes.h
and uinput.h (GPL-2.0 WITH Linux-syscall-note). These are numeric constants and
struct field orders, used so the device this creates identifies itself to the
kernel and to games as an ordinary Xbox 360 pad. The notice is for provenance:
the numbers came from there, and when they drift the bug shows up as a controller
that half works.

4. Shipped inside the AppImage
------------------------------

  AppImage runtime         MIT, the AppImage project contributors
    https://github.com/AppImage/AppImageKit

  The type-2 runtime ELF is prepended to GlassPad-<version>-x86_64.AppImage. The
  squashfs payload was produced with mksquashfs (GPL-2.0), which is used at build
  time and is not part of the output.

  Recorded for honesty: on the machine this was built, squashfs-tools and
  appimagetool were unavailable, so the runtime was extracted from another
  AppImage already present and the payload packed by borrowing a mksquashfs
  binary. Installing squashfs-tools and appimagetool removes that dependency; the
  build script prints which it borrowed on every run.

  The .run bundle contains no third-party binary at all: its launcher is POSIX sh
  with a zip payload, which is also why it needs no FUSE.

5. Fonts
--------

None shipped. The client asks for "Segoe UI" by name and leaves the substitution
to your fontconfig, which is what the Windows client effectively does too —
hardcoding a fallback would be wrong on a machine that does have Segoe UI.

6. Not part of this build
-------------------------

HIDMaestro, usbip-win2 and DsHidMini are shipped in neither artefact. They belong
to the Windows original's transport: HIDMaestro presents a real USB device through
a Windows kernel driver, and usbip-win2 and DsHidMini are its dependencies and
report-descriptor reference.

This port creates its device through the Linux kernel's uinput interface and links
none of that code. Their licence texts were held under licenses/windows-original/
and were removed when the repository was trimmed to what this build needs; they
stay recoverable from the project's git history. Nothing here requires them, and
nothing here uses them -- this section exists so that a reader who knows the
Windows original is not left wondering where its notices went.
